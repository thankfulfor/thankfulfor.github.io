## Контекст

Небольшая внутренняя задача: описать Socket.IO-метод, у которого не было готового контракта.

[PastVu](https://PastVu.com) — онлайн-архив фотографий и картин. Пользователи обсуждают материалы в комментариях; часть обмена между клиентом и сервером проходит через Socket.IO.

Я задокументировала внутренний метод `comment.create`. Он создаёт комментарий к фотографии или новости и вызывается на клиенте как Socket.IO action:

```js
socket.run('comment.create', dataSend, true)
```

## Задача

Описать метод `comment.create`: какие параметры он принимает, что возвращает, какие ошибки возможны и где это подтверждается в коде.

## Что было сложно

В исходном коде PastVu контракт `comment.create` не вынесен в OpenAPI/AsyncAPI-схему или типизированный интерфейс. Параметры и структуру ответа пришлось собирать по частям.

Контракт пришлось восстановить по нескольким источникам: frontend-вызову, backend-проверкам, моделям данных и реальным Socket.IO frames из локального окружения.

## Как восстановлен контракт

Метод `comment.create` позволяет авторизованному пользователю:

1. Добавить комментарий первого уровня к фотографии или новости.
2. Ответить на существующий комментарий.
3. Добавить комментарий к выделенному фрагменту фотографии.

Метод также ограничивает вложенность ответов и проверяет, что ответ привязан к существующему неудалённому родительскому комментарию.

## Reference: `comment.create`

Метод `comment.create` позволяет авторизованному пользователю добавить комментарий к фотографии или новости, а также ответить на существующий комментарий.

### Request payload

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| obj | number | да | `cid` фотографии или новости, к которой добавляется комментарий. |
| txt | string | да | Текст комментария. Максимальная длина — 12 000 символов. |
| type | string | нет¹ | Тип объекта, к которому добавляется комментарий. Значения frontend-вызова: `photo` для фотографии, `news` для новости. |
| parent | number | нет | `cid` родительского комментария, к которому добавляется ответ. |
| level | number | да, если передан parent | Уровень вложенности ответа. Передаётся вместе с `parent` и равен уровню родительского комментария + 1. Максимальный уровень вложенности – 9. |
| fragObj | object | нет | Координаты выделенного фрагмента фотографии в процентах. Используется только для комментариев к фотографии. Поля: `l`, `t`, `w`, `h`. |

¹Backend не проверяет наличие `type` явно. Во frontend-вызове `type` передаётся всегда: `photo` для фотографии и `news` для новости.

#### Поля объекта `fragObj`
`fragObj` содержит координаты выделенной области фотографии в процентах от размера изображения.

| Поле | Тип | Описание |
|---|---|---|
| l | number | Отступ слева от изображения, в процентах. |
| t | number | Отступ сверху от изображения, в процентах. |
| w | number | Ширина выделенного фрагмента, в процентах. |
| h | number | Высота выделенного фрагмента, в процентах. |

### Response payload

В случае успешного ответа метод возвращает объект с двумя полями:

| Поле | Тип | Описание |
|---|---|---|
| comment | object | Созданный комментарий. |
| frag | object | Данные фрагмента фотографии. Поле присутствует только если комментарий добавлен к выделенному фрагменту фотографии. |

#### Поля объекта `comment`

| Поле | Тип | Описание |
|---|---|---|
| cid | number | `cid` созданного комментария. |
| obj | number | `cid` фотографии или новости, к которой добавлен комментарий. |
| user | string | Логин пользователя, создавшего комментарий. |
| txt | string | Текст комментария после обработки backend. |
| can | object | Объект прав для комментария. В момент создания возвращается пустым объектом. |
| level | number | Уровень вложенности комментария. Для комментария верхнего уровня — `0`. |
| parent | number | `cid` родительского комментария. Возвращается только для ответа на комментарий. |
| frag | boolean | `true`, если комментарий привязан к фрагменту фотографии. |
| stamp | string | Дата и время создания комментария в ISO-формате. |
| s | number | Статус фотографии. Копируется из объекта фотографии при создании комментария к фотографии. |
| type | number | Тип изображения: `1` — фотография, `2` — картина. Копируется из объекта фотографии при создании комментария к фотографии. |
| geo | Array<number> | Координаты фотографии в формате `[lng, lat]`. Возвращается только для комментариев к фотографии, если координаты есть у фотографии. |
| r0–r5 | number | Идентификаторы регионов фотографии по уровням вложенности. Возвращаются только для комментариев к фотографии. |

> Важно: поле `type` в request payload и поле `comment.type` в response payload имеют разный смысл.  
> В запросе `type` — строка `photo` или `news`, которая определяет тип комментируемого объекта.  
> В ответе `comment.type` — числовой тип изображения: `1` для фотографии, `2` для картины.

#### Поля объекта `frag`

`frag` содержит координаты выделенной области фотографии в процентах от размера изображения. Возвращается только если комментарий добавлен к фрагменту фотографии.

| Поле | Тип | Описание |
|---|---|---|
| cid | number | `cid` комментария, к которому относится фрагмент. |
| l | number | Отступ слева от изображения, в процентах. |
| t | number | Отступ сверху от изображения, в процентах. |
| w | number | Ширина выделенного фрагмента, в процентах. |
| h | number | Высота выделенного фрагмента, в процентах. |

В request payload координаты передаются в поле `fragObj`, а в response payload возвращаются в отдельном объекте `frag`.

### Ошибки

| Ошибка | Когда возникает | Что это значит | Что делать |
|---|---|---|---|
| `AuthorizationError` | Пользователь не авторизован. | Комментарии могут оставлять только зарегистрированные и авторизованные пользователи. | Попросить пользователя войти в аккаунт и повторить действие. |
| `BadParamsError` | В запросе нет обязательных данных или данные переданы в неверном формате. | Сервер не может создать комментарий без объекта комментария или текста. | Проверить, что переданы `obj` и `txt`, а уровень вложенности не больше `9`. |
| `InputError: COMMENT_TOO_LONG` | Текст комментария длиннее `12 000` символов. | Сервер отклоняет слишком длинные комментарии. | Сократить текст комментария до `12 000` символов. |
| `NotFoundError: COMMENT_NO_OBJECT` | Фотография или новость не найдена. | Объект, к которому добавляют комментарий, не существует или недоступен. | Проверить `cid` фотографии или новости. |
| `NoticeError: COMMENT_NOT_ALLOWED` | Комментарии к объекту запрещены. | У фотографии или новости отключено комментирование. | Сообщить пользователю, что для этого объекта комментарии недоступны. |
| `NoticeError: COMMENT_WRONG_PARENT` | Ответ привязан к некорректному родительскому комментарию. | Родительский комментарий удалён, не найден или превышен лимит вложенности. | Обновить страницу/ветку комментариев и попробовать ответить заново. |
| `ApplicationError: COUNTER_ERROR` | Сервер не смог создать новый `cid` комментария. | Внутренняя ошибка сервера при генерации идентификатора. | Передать разработчикам как технический инцидент. |

#### Технические условия для разработчиков

| Ошибка | Условие в коде |
|---|---|
| `AuthorizationError` | `!iAm.registered` |
| `BadParamsError` | `!_.isObject(data)`, `!Number(data.obj)`, `!data.txt`, `data.level > 9` |
| `InputError(COMMENT_TOO_LONG)` | `data.txt.length > commentMaxLength`, где `commentMaxLength = 12000` |
| `NotFoundError(COMMENT_NO_OBJECT)` | `!obj` |
| `NoticeError(COMMENT_NOT_ALLOWED)` | `obj.nocomments` |
| `NoticeError(COMMENT_WRONG_PARENT)` | `data.parent && (!parent \|\| parent.del \|\| parent.level >= 9 \|\| data.level !== (parent.level \|\| 0) + 1)` |
| `ApplicationError(COUNTER_ERROR)` | `!cid` |


## Примеры

Примеры основаны на локальных Socket.IO-вызовах. Значения `cid`, `rid`, времени, координат и текста приведены как пример.

`rid` и `responseTime` относятся к транспортной обёртке ответа. Результат выполнения `comment.create` находится в поле `result`.

#### 1. Комментарий к новости

Socket request frame:

```json
[
  "comment.create",
  {
    "type": "news",
    "obj": 148,
    "txt": "Это комментарий к новости"
  }
]
```

Socket response payload:

```json
{
  "result": {
    "comment": {
      "cid": 15,
      "obj": 148,
      "user": "admin",
      "stamp": "2026-07-03T16:17:14.200Z",
      "txt": "Это комментарий к новости",
      "can": {},
      "level": 0
    }
  },
  "rid": "e9o25r7c25",
  "responseTime": 19
}
```

#### 2. Комментарий первого уровня к фотографии

Socket request frame:

```json
[
  "comment.create",
  {
    "type": "photo",
    "obj": 2,
    "txt": "Это комментарий первого/верхнего уровня"
  }
]
```

Socket response payload:

```json
{
  "result": {
    "comment": {
      "cid": 13,
      "obj": 2,
      "user": "admin",
      "stamp": "2026-07-03T16:12:43.224Z",
      "txt": "Это комментарий первого/верхнего уровня",
      "can": {},
      "level": 0,
      "geo": [-121.596679, 33.027375],
      "r0": 1000000,
      "s": 5,
      "type": 1
    }
  },
  "responseTime": 31,
  "rid": "bvo2t8zcvb"
}
```

#### 3. Ответ на комментарий

Socket request frame:

```json
[
  "comment.create",
  {
    "type": "photo",
    "obj": 2,
    "txt": "Это ответ на комментарий первого/верхнего уровня",
    "parent": 13,
    "level": 1
  }
]
```

Socket response payload:

```json
{
  "result": {
    "comment": {
      "cid": 14,
      "obj": 2,
      "user": "admin",
      "stamp": "2026-07-03T16:14:28.941Z",
      "txt": "Это ответ на комментарий первого/верхнего уровня",
      "can": {},
      "level": 1,
      "parent": 13,
      "geo": [-121.596679, 33.027375],
      "r0": 1000000,
      "s": 5,
      "type": 1
    }
  }
}
```

#### 4. Комментарий к фрагменту фотографии

Socket request frame:

```json
[
  "comment.create",
  {
    "type": "photo",
    "obj": 2,
    "txt": "Это комментарий к фрагменту",
    "fragObj": {
      "l": 10.9,
      "t": 6.487341772151899,
      "w": 23.3,
      "h": 36.86708860759494
    }
  }
]
```

Socket response payload:

```json
{
  "result": {
    "comment": {
      "cid": 16,
      "obj": 2,
      "user": "admin",
      "stamp": "2026-07-03T16:20:20.986Z",
      "txt": "Это комментарий к фрагменту",
      "can": {},
      "level": 0,
      "frag": true,
      "geo": [-121.596679, 33.027375],
      "r0": 1000000,
      "s": 5,
      "type": 1
    },
    "frag": {
      "cid": 16,
      "l": 10.9,
      "t": 6.48,
      "w": 23.3,
      "h": 36.86
    }
  },
  "responseTime": 21,
  "rid": "e9kb5j811r"
}
```

В request payload фрагмент передаётся как `fragObj`. В response payload backend возвращает отдельный объект `frag`, а в объект `comment` добавляет поле `frag: true`.
